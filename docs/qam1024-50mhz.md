# 1024QAM and a 50 MHz carrier

Two additions to the simulator and to the codeword-mapping study script (`examples/cw2lm_ftp_eval.py`), 2026-11-11. With the default settings nothing changes: the logged `20mhz-ftp1` runs reproduce bit for bit.

## 1024QAM

- **MCS table 4** (`FullBufferConfig.mcs_table = 4`) is TS 38.214 Table 5.1.3.1-4, the Rel-17 table: 27 rows (indices 0–26), 3 QPSK, 3 16QAM, 9 64QAM, 8 256QAM and 4 1024QAM rows with R × 1024 = 805.5, 853, 900.5 and 948 (7.87 to 9.26 bit per symbol). It comes with **CQI table 4** (TS 38.214 Table 5.2.2.1-5), whose CQIs 14 and 15 are 1024QAM.
- **Where it lives.** `nrdlsim` has a table 4 of its own that it calls illustrative: its 256QAM table with six 1024QAM rows appended, 34 indices. `nrsls/mac/mcs_table4.py` replaces it in `nrdlsim`'s table registry when `nrsls` is imported, so table 4 means the Rel-17 table everywhere. The better place for the table is `nrdlsim` itself.
- **How sure the values are.** The four 1024QAM rows match the RAN1 #104-e agreement. Rows 0–22 are rows of the 256QAM table; which five of that table's QPSK and 16QAM rows the Rel-17 table drops was entered from memory of the specification and has not been checked against it here. The dropped rows sit between −1 and 10 dB.
- **1024QAM mutual information.** `nrdlsim` builds the BICM curve of a modulation by Monte Carlo on first use (about 30 s for 1024QAM) and caches it on disk.

### EVM

1024QAM needs 28.4 dB of post-equaliser SINR for its lowest rate and 32.2 dB for its highest; 256QAM's highest rate needs 26.7 dB (10 % BLER, one layer on 52 PRB). The simulator has ideal transmitters and receivers, so without a limit a strong layer reaches 35–40 dB, which no real link does.

`FullBufferConfig.evm_percent` (default 0, no limit) sets an error-vector magnitude for the link, transmitter and receiver together. Every post-equaliser SINR, in the CSI report and in the decoding, becomes

    SINR' = 1 / (1 / SINR + EVM²)

which is at most 1 / EVM²: 32.0 dB at 2.5 %, 29.1 dB at 3.5 %. TS 38.104 lets a BS have an EVM of 3.5 % with 256QAM and 2.5 % with 1024QAM. This is the usual system-level simplification: the distortion is treated as white noise on each layer, in proportion to that layer's signal.

### What 1024QAM gives in Dense Urban A

NR, sub-band SVD, FTP model 1 at the 20 % load of `20mhz-ftp1`, drops 0 and 1 on the logged traffic, files that arrived in the first 700 of 1000 slots. These are 2 drops, a first look and not a result:

| MCS table, EVM | Mean UPT, drop 0 / 1 [Mbit/s] | Against 256QAM without EVM | 95th-percentile UPT [Mbit/s] | 1024QAM share of new TBs |
|---|---|---|---|---|
| 256QAM, none | 124.0 / 121.2 | | 243.5 / 242.9 | |
| 256QAM, 2.5 % | 124.5 / 121.7 | +0.4 / +0.4 % | 245.7 / 240.8 | |
| 1024QAM, none | 133.0 / 124.5 | +7.2 / +2.7 % | 249.4 / 240.0 | 18.5 / 16.1 % |
| 1024QAM, 1.5 % | 129.5 / 123.2 | +4.4 / +1.6 % | 238.4 / 239.5 | 16.4 / 12.6 % |
| 1024QAM, 2.5 % | 123.0 / 120.5 | −0.8 / −0.6 % | 224.9 / 223.5 | 7.5 / 8.1 % |

- **The gain depends on the EVM.** With ideal hardware 1024QAM carries a sixth of the TBs and adds 3–7 % mean UPT. At the 2.5 % a BS is allowed, it carries 8 % of them and adds nothing.
- **Why the top users lose at 2.5 %.** With 256QAM a user above 27 dB sits on the highest MCS and almost never fails. With 1024QAM the same user climbs until OLLA holds it at 10 % BLER, 6–12 % more bits per TB against a tenth of the TBs sent twice and a file that more often waits a HARQ round trip for its last TB. The 95th-percentile UPT is 8 % lower.
- **Codeword mapping.** With 1024QAM and 2.5 % EVM, LTE style gains +2.4 / +0.9 % and one codeword per layer +1.5 / +1.1 % mean UPT over NR on these two drops (with 256QAM and no EVM: +3.3 / +4.1 % and +2.6 / +3.4 %). 1024QAM on the strongest layer does not add to the multi-codeword gain here.

## 50 MHz carrier

Set-up `50mhz-ftp1` of `examples/cw2lm_ftp_eval.py`:

| | `20mhz-ftp1` | `50mhz-ftp1` |
|---|---|---|
| Carrier | 30 kHz SCS, 52 PRB | 30 kHz SCS, 133 PRB (TS 38.101-1 Table 5.3.2-1) |
| BS power | 44 dBm | 48 dBm: the same power per Hz, M.2412 gives 44 dBm per 20 MHz |
| RBG and CSI sub-band | 4 PRB | 8 PRB (TS 38.214 Tables 5.1.2.2.1-1 and 5.2.1.4-2 for 73–144 PRB) |
| UPT and SE normalised by | 20 MHz | 50 MHz |

Everything else is as in `20mhz-ftp1`: Dense Urban-eMBB A at 4 GHz, 32T and 4R, FTP model 1 with 0.5 Mbyte files and a pool of 20 UTs per cell, CSI every 20 ms and 4 ms old, 8-slot HARQ round trip. At 20 % load a file now takes about 33 slots from arrival to its last bit (72 at 20 MHz), 8 of which are the wait for the first CSI report, so the start and the end of a file weigh more than at 20 MHz. `FILE_BYTES` in the script changes the file size.

A 1000-slot run at 20 % load takes about 1.6 times as long as a 20 MHz run (about 100 s against 60 s on the machine used here).

## Set-ups in the study script

| `--setup` | Carrier | MCS table, EVM | Arrival rates |
|---|---|---|---|
| `50mhz-ftp1` | 50 MHz | 256QAM, none | `results/cw2lm_ftp1_rates_50mhz.json` |
| `20mhz-ftp1-1024qam` | 20 MHz | 1024QAM, 2.5 % | those of `20mhz-ftp1` |
| `50mhz-ftp1-1024qam` | 50 MHz | 1024QAM, 2.5 % | those of `50mhz-ftp1` |

A 1024QAM set-up runs on the arrival rates of its 256QAM set-up, so a load is the RU of NR with 256QAM on that carrier, and the 256QAM and 1024QAM runs of a case, load and drop see the same users and files. Records of new runs carry `modulation_share`, the QPSK / 16QAM / 64QAM / 256QAM / 1024QAM shares of the new TBs (`FullBufferResult.modulation_share`).

```bash
python examples/cw2lm_ftp_eval.py --setup 50mhz-ftp1 --cases svd_sb_20ms,svd_20ms \
    --calibrate --cal-drops 1 --cal-slots 2300 --log results/ftp1_50mhz_cal/cal.jsonl
python examples/cw2lm_ftp_eval.py --setup 50mhz-ftp1 --cases svd_sb_20ms,svd_20ms \
    --variants irc-fix-warmfast,sic-fix-warmfast --loads 20,50 --slots 1000 --warmup 0 --drain 0 \
    --drops 10 --log results/ftp1_50mhz/runs.jsonl
python examples/cw2lm_ftp_eval.py --setup 20mhz-ftp1-1024qam ...        # the same, 1024QAM
```

The 50 MHz arrival rates were calibrated on drop 0 only (the 20 MHz ones on two drops); the log is in `results/ftp1_50mhz_cal/`.

## Limits

- **EVM model.** One number for transmitter and receiver, white and proportional to each layer's own signal. Distortion that is not beamformed with the signal, phase noise and channel-estimation error are not modelled separately.
- **SIC and EVM.** A cancelled codeword's distortion cannot be cancelled; the model only limits each layer's own SINR.
- **Single-link harness.** `engine/single_link.py` (the LLS regression) does not model the EVM and rejects `evm_percent > 0`.
- **MU-MIMO.** The limit applies there too, but 1024QAM with MU-MIMO has not been run.
